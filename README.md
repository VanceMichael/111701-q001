# 码头堆场提箱预约采集服务

这是一个用于码头堆场提箱预约的本地数据采集与归档服务。当前版本从仓库自带的合成来源记录读取一页数据，经过字段规整后写入进程内目录；来源内容和规整后的记录保留独立边界，便于在不访问外部系统的情况下复现采集过程。

## 运行

需要 Node.js 20 或更高版本，不需要安装第三方依赖。

```sh
npm test
npm run build
node src/pipeline.mjs
```

测试使用项目内的合成记录；执行不需要网络、凭据或外部服务。

## 预约、车辆与凭证的对应关系

- **预约身份**：`source + id`（提箱预约号）。车辆安排只是预约上的关联字段，不会覆盖预约身份。
- **业务内容**：泊位、提箱时间窗、车辆（车牌/司机/车位时段）和修订号共同决定预约的“当前版本”。
- **入场凭证**：由 `issueGatePass` 生成，凭证号由预约身份、修订号和业务内容指纹共同计算。预约改期、换泊位或换车都会产生新凭证，旧凭证随即失效。
- **验票**：`verifyGatePass` 必须对照记录库中的最新状态，而不是只看凭证本身。旧凭证会返回 `SUPERSEDED`。

## 采集失联时的语义

`collect` 在来源读取失败时**不写入任何新内容**，并把该来源已有记录降级为 `unconfirmed`（待确认），同时记录原因和时间。此时：

- 不生成凭证，`result.credentials` 为空；
- `issueGatePass` 对非 `confirmed` 记录抛出 `UNCONFIRMED`；
- 之前发出去的旧凭证在验票时返回 `UNCONFIRMED`，闸口不能再把它当作最新凭证放行。

来源恢复后，成功采集到的页面会重新确认为 `confirmed`。来源页标记 `complete: false`（分页/截断）时，不会把本页未出现的预约判为失效。

## 修订与乱序

- 修订号更大的记录覆盖旧记录；修订号相同时以观察时间较新者为准。
- 乱序到达的旧修订会被拒绝并记录 `rejected-older` 事件，不会回滚已确认内容。
- 同一修订、同一观察时间但内容不同：保留已确认内容，标记 `conflict` 并记录 `conflict` 事件。
- 修订号未变、观察时间更新且内容变化：采用新内容，并标记 `anomaly: 'CONTENT_CHANGED_WITHOUT_REVISION'` 留痕。

所有判定都会写入 `store.events()`，便于追溯预约变更、车辆安排与凭证的对应过程。
